## Live desk-v2 facts that shape the chart
- **The act model exists.** `frontend/src/acts/dispatcher.ts`: an act's full name is `<surface>.<item>`. An `ActItem` has `name`, `label`, `run(context, value)`, `key`, `right`, `when`, `palette:false` and an optional `argument` (a palette option picker). A page registers `ActScope.surfaces` with the dispatcher (the record page's `pageActs.ts` registers `header`, `quickActions`, `tabs`). `page.run(name, value)` takes **one** value, so an act with several arguments takes one object, and it is `palette:false` unless it has an `argument` picker or opens a dialog when it runs with no value.
- **`FormLayout`** (`ui/src/components/FormLayout/`) has no edit seam. Its props are `layout`, `autofocus` and `doctype`. Sections, columns and fields render in plain `v-for` loops. A column drops hidden fields. `Section` has no `description` and `Column` has no `dependsOn`. `resolveLayout` bakes tab and section `dependsOn` into `hidden`.
- **`get_meta_layout`** (`form_layout.py:596`) keeps only a break's `name` and `label`. `buildLayoutFromMeta` (client) already carries section `dependsOn`, `collapsible` and `hide_border`.
- **`Form Layout` fields:** `dt, type, app, dialog_size, condition, layout, omitted`. It has no `title` and no `fingerprint`. `save_form_layout(dt, type, layout, name, condition, app)` has no `base_version`. `check_layout_access` calls `has_permission(child, "read")`, which returns 403 for a child to anyone who is not Administrator.
- **App tier** (`app_layout.py`): `read_app_layout` reads ONE file per type, `<dt>/frontend/layouts/<type>.json`, holding `{layout, omitted, size}`. It has **no condition and no title**. Nothing writes these files yet. Per E1 the file becomes a list of layouts (slice S-d). `DocType.export_files()` and `write_doctype_files` (#45903) are the hook for a writer.
- **Not present:** an editor page or route, an editor save endpoint, a whitelisted `rename_field` wrapper, desk-v2 reads of `DocField.link_filters` (v1 `link.js` and `frappe.client.validate_link` already apply them), live `fetch_from`, a reader of `collapsible_depends_on`, the `in_list` and `cint` globals in `dependsOn.ts`, and a grid that honours `columns`.

## A. Act surface

Rule (#45866 r1, Facts): each **edit act** is one entry kind in the save's `edits` (`{doctype, mode, base_version, edits:[…]}`, grouped by DocType for a new child, r12). The same act writes to different places in each mode (r13). The server, not the client, decides between a fork, an anchor and `field_order` (#45865 r3, r8). **UI acts** change no state the save sends. **Immediate acts** run at once from their own dialog (#47098 Saving).

Proposed surfaces (the dispatcher's first name part): `editor`, `layouts`, `canvas`, `fields`, `settings`, `danger`, `customize`. D = Design, C = Customize.

## B. Edit seam

**What the prototype did.**
- **2026-10-30 (in-place, abandoned):** a `LayoutEditKey` inject in `FormLayout.vue`, `FormLayoutSection.vue` and `FormLayoutColumn.vue`. The editor supplied wrapper components for the section, column and field lists, and `FormLayout` showed hidden containers and skipped `resolveLayout` in edit mode. It took about 60 lines and left the record page unchanged when the key was absent.
- **2026-11-12 (ruled look):**
  - The editor draws tabs, sections and columns itself: `create/EditorCanvas.vue`, `SidePanelCanvas.vue`, a 576px dialog frame for Quick Entry, and vuedraggable.
  - Each field is `create/EditorField.vue`: frappe-ui `FormControl`/`TextInput` look-alikes in an `inert` div, not `FormLayoutField`. A Table field is `CanvasGrid.vue`.
  - Only the Preview tab (`FormPreview.vue`) renders the real `FormLayout`, with a real record, `NO_COMMIT`, and `link_filters` applied.
  - `PanelLayout` is never used, because it is tied to `RecordPageApi` (`page.panelSections`).

**What the resolutions require.**
- Charter ruling 9: the canvas renders with `FormLayout` / `PanelLayout`.
- The ruled look, which a renderer does not draw:
  - CRM #3419's rings and grips, the section "Add field" with its type chip, "Add tab" and "Add section";
  - a tab strip that accepts a dropped field;
  - "Drop a field here" boxes in empty columns, and section labels edited in place;
  - condition marks and Customize marks;
  - every container visible, collapse disabled, the read-only grid of a Table field;
  - the 728px Details column, the Side panel as a 380px column in the record panel's look with built-ins as one gray locked block, and Quick Entry inside a 576px Create-dialog frame (#45867, #47097, #47099, #47100).
- Preview: one frame with the record page's tab strip (#47097 Q17).

**Options.**
1. **Editor-owned containers, shared field face (recommended).** The editor draws the containers in the ruled look. Each field renders the record page's real `FormLayoutField` (exported from ui), drawn `inert` with an empty doc and `NO_COMMIT`. A Table field renders the real `TableField` with no rows, so the grid honours `columns`. The container classes and widths come from the record page (`FORM_CLASSES`, 728px). The Preview tab is the real renderer. `FormLayout` and `PanelLayout` gain only renderer features: section `description`, column `dependsOn`, and E2.
2. **An inject seam in `FormLayout` (the 10-30 `LayoutEditKey`).** The renderer's lists delegate to draggable wrappers that the editor provides.
   - For: ruling 9 holds as written, and container spacing is the renderer's own.
   - Against: every ruled affordance above needs a slot inside a ui component that the record page, dialogs and the row dialog all use, which is a wide API to keep stable. `PanelLayout` needs a fake `RecordPageApi`, so the Side panel canvas cannot use it. The owner ruled the look on option 1's shots.
3. **Hybrid:** option 2 for Details and New Record, option 1 for the Side panel and Quick Entry. Two canvases to keep in step, for little gain.

**Recommendation: option 1.** It is the look the owner ruled. It keeps `FormLayout`'s public API small. It needs no fake page for `PanelLayout`. Each field is still the real control. The Preview tab, with a real record, gives full fidelity. The owner amended charter ruling 9 to this option (E4): `FormLayout` gets no edit seam. The seam is small and ships in slice S-g: export `FormLayoutField` and make it inert-capable (no commit, no Link search until opened, which is already lazy).

## E. Owner decisions (resolved)

All seven were resolved on 2026-11-13 in [#47262](https://github.com/frappe/frappe/issues/47262) ("go with rec"). Sections A to D above carry the answers.

- **E1 (A).** An app layout file holds a list of layouts, each with an optional `title` and `condition`, at most one with no condition per type. The layout menu works the same in both modes. `read_app_layout` and the writer change to match (S-d).
- **E2 (A).** A section node gets `collapsibleDependsOn`. This amends #45863. The renderer and the fallback honour it (S-a); the panel's "Starts open if" writes it (S-m).
- **E3 (A).** Design hides site custom fields, also the ones other apps add, with the note "N fields added on this site, edit them in Customize ↗". The save refuses an app layout that names one. This supersedes #45866 r9 (S-e load, S-f save, S-g note).
- **E4 (yes).** Charter ruling 9 is amended: the Preview tab is the real renderer (`FormLayout`, and `PanelLayout` for the Side panel); the canvas draws its own containers and each field with the record page's real control, inert. `FormLayout` gets no edit seam (S-g).
- **E5 (A).** One undo and redo stack for the Editor and Settings tabs. ⌘Z undoes the last staged edit from either tab. Danger-zone acts stay outside (S-e builds the stack; S-l1 puts Settings on it).
- **E6 (A).** Every layout type, Details included, has a collapsible "Fields not on this layout" tray with the "new since the save" and "asked for on save" marks; ⌘J finds these fields too (S-g on Details, S-j on the others).
- **E7.** The DocType description is a light text typed in place under the name in the header, as #45867 Q5 ruled; Settings has no row for it (S-g).
