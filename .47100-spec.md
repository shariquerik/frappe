# #47100 prototype spec (throwaway; read with .47099-spec.md)

Question: how does a person set a field's conditions (Visible if, Mandatory if, Read-only if), Fetch from and link
filters without writing code? Research facts: `/tmp/proto-47100/research.md` (file:line for every claim below).

## Facts (short)
- Conditions are JavaScript: `eval:<expr>` with `doc` (record or row) and `parent`, or a bare fieldname (truthy; a
  table must have rows). `fn:` is v1 only. The server never evaluates them; `mandatory_depends_on` is client-only.
- Desk v2 (`ui/.../FormLayout/dependsOn.ts:37-52`): an `eval:` that throws counts as TRUE (shown). No `in_list`,
  `frappe`, `cint` globals on the v2 page, so conditions using them are always true there.
- Real use, 7 apps: 2078 `eval:` conditions; 74% a single comparison or a flat &&/|| chain, 6% mixed &&/|| (needs
  nested groups), 20% need code. `parent.` 122, `__islocal` 127, `docstatus` 80, `in_list(` 52, `.includes(` 75.
- `collapsible_depends_on` has no reader in desk v2. NEW (this build): desk v2's meta layout (`get_meta_layout`,
  form_layout.py:596-617) keeps only a break's name and label, so a Section or Tab Break's `depends_on`,
  `collapsible` and `collapsible_depends_on` never reach the record page of a DocType with no Form Layout row
  (checked: T-SINV-00008, not POS, shows the Write Off section, whose break has `depends_on: is_pos`).
- `fetch_from` = `<link_fieldname>.<source_fieldname>`; validation only refuses a self-fetch. Desk v2 does not fetch
  on Link change (server fetches at save). `fetch_if_empty`: without it the value is re-fetched on every save.
- `link_filters` = JSON `[[doctype, field, op, value]]`, flat AND; value may be `eval:doc.company`. Desk v2 reads no
  `DocField.link_filters` (only page-script `link_filters` → `meta.filters`). ERPNext narrows Links with
  `frm.set_query` (615 calls) instead; only 48 fields use `link_filters`.
- Customize Form allows all of them by Property Setter (`docfield_properties`: fetch_from, fetch_if_empty,
  collapsible, collapsible_depends_on, mandatory/read_only/depends_on, link_filters).

## What is built (branch `proto/doctype-editor`)
Demo: Sales Invoice (submittable, ERPNext) with its real conditions; Sales Invoice Item for `parent.` rows; the custom
Store DocType works too (one field). Steps `.proto-shots/conditions.json` (+ `conditions-shariq.json`, `SID_FILE=`).

- `conditions.ts`: a tokenizer + recursive-descent parser for the simple JS subset into ui's ConditionBuilder tree
  (`||`/`&&` precedence, `!`, parens, `==`/`===`/`!=`/`!==`/`<`/`>`, `in_list([...], doc.x)`, `[...].includes(doc.x)`,
  `[...].indexOf(doc.x) !== -1`, `doc.x.includes("y")`, `doc.items.length`, `parent.x`, `doc.__islocal`,
  `doc.docstatus`, field-vs-field comparisons, trailing `;`). Anything else (unknown names, calls, `!(a && b)`,
  `doc.items` without `.length`) is refused, so the condition stays code, untouched. A JS emitter writes `eval:` back
  (`===`, `!==`, `&&`, `||`, `!`, `[...].includes`, `(doc.x || "").includes`), or the bare fieldname when the tree is a
  single "is set"/"is on". Round trip checked on 26 real expressions (parse → emit → parse gives the same tree).
  The stored string is rewritten only when the person edits the rule.
- Panel rows: Conditions group = Visible if / Mandatory if / Read-only if, each ONE line in words ("Always", "Never",
  "Return Against is set or Is Rate Adjustment Entry (Debit Note) is on", or the code in mono with a code icon),
  with a Tooltip giving the full sentence ("Starts open if Include Payment (POS) is off"), chevron at the shared right edge. Click opens the builder.
- Builder (`ConditionEditor.vue`): ui's ConditionBuilder, `fields` = this DocType's fields (Table fields as
  "Items (has rows)"), "Parent: <label>" fields on a child row (`parent.x`), "Record is new" (Check, Yes/No → "Record
  is new"/"Record is saved"), "Document status" (Draft/Submitted/Cancelled → 0/1/2) on a submittable DocType.
  maxDepth 3, root card removed (no card in the card; nested groups keep theirs), empty state = gray note + "Add
  condition". Rules | Code switch; Code = the JS after `eval:` (mono Textarea); Rules is disabled with a Tooltip while
  the code is unreadable; an unreadable condition opens in Code with "The rules can't show this condition. It stays
  as code, as written." Footer: Clear condition, Done. A value can be "a field of this record"
  (the `(x)` button at the value's end; `doc.uom !== doc.stock_uom` reads "UOM differs from Stock UOM").
- Sections: Collapsible switch; Conditions = Visible if, Starts open if (`collapsible_depends_on`, only when
  collapsible). Tabs: Visible if. Both write the tree and the break field.
- Canvas: a gray `lucide-split` mark after a field's label (and before a section's grip) when it has a condition; its
  Tooltip says each rule in words, one per line, at most 320px wide.
- Preview: FormLayout already evaluates `depends_on` from the schema, so a rule edited in the builder shows live;
  link filters are applied to the Link's search (`{"is_group":0,"company":"_Test Company"}`).
- Fetch from: moved from "List and search" to the Field group under Default. Row "Customer › Tax ID" / "None";
  popover (320px, right edges together): step 1 Link fields of this form (target in gray; the label keeps its width, the target truncates first), step 2 "Fields of
  Customer" with search, type icons and a check on the chosen one; "Stop fetching". "Only when empty" switch
  (`fetch_if_empty`) under it when set, with what each state does.
- Link filters: "Filters" row under "Links to" ("All customers" / "Disabled is No · Customer Group is Commercial"),
  same builder against the TARGET DocType's filterable fields, flat AND ("and" as text, gray × to remove), JSON code
  view. Values may be a field of this record (`eval:doc.company`).
- Customize: `link_filters` and `collapsible_depends_on` joined WATCHED; rows get the changed dot + reset; sections
  get marks for their rules.

## Variants
`?cond=` (VariantBar `param="cond"`, SavedPage's one bar now; `?child=` reads from the address and defaults to C
since the owner amended #47099; `?child=A|B` keep the others):
- A popover (default, rec): 600px, below the row, right edge on the row's, over the canvas; the panel scrolls the row
  up (padding its end if needed) so it never flips above; height capped to the room below.
- B dialog: size 2xl, title "Visible if · Return Against"; Rules | Code, Clear, Done in its footer.
- C inline: under the row, a full-bleed gray band in the 380px panel. Too narrow: fields truncate to "Is R…".
`?fetch=B`: a Link field's panel adds "Fetched fields": "+ Fetch a field…" (step 2 of the picker on Customer) and "Fetched now: Customer Name, Tax ID and 6 more."; a pick adds a read-only field after the Link with
`fetch_from` set, selected. A (default): Fetch from on the target field only.

## What is faked
- Every write: edits stay in memory and join Save's toast; Property Setters are not written.
- Section/Tab rules are read back from the break fields at load (the build must make `get_meta_layout` carry them).
- Sales Invoice's Source Warehouse is seeded with `link_filters` `[["Warehouse","is_group","=",0],["Warehouse",
  "company","=","eval:doc.company"]]` (Sales Invoice has none; ERPNext uses set_query).
- Desk v2 ignores DocField `link_filters` and has no live fetch; only the Preview applies the filters, and nothing
  fetches live.
- `collapsible_depends_on` is edited but nothing in desk v2 reads it (Preview shows no change).
- The value cell imports Filter's `valueControl`/`VALUE_CONTROLS` by deep path (eslint-disabled); the build needs an
  export or a value-cell suffix slot on ConditionBuilder.
- No count of records a condition hides; no check that a rule names a field that still exists after a rename.
